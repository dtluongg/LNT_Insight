Lỗi "Maximum update depth exceeded" xảy ra do vòng lặp điều hướng vô hạn (Infinite Redirection Loop) giữa trang chủ / và /dashboard.

1. Nguyên nhân chi tiết
Hãy cùng phân tích luồng chạy của Router trong file 

routes.tsx
:

Bước 1: Khi ứng dụng khởi chạy hoặc người dùng đã đăng nhập thành công:
Nếu truy cập /, route index 

<Route index element={<Navigate to="/dashboard" replace />} />
 sẽ chuyển hướng người dùng sang /dashboard.
Nếu ở trang /login mà đã đăng nhập, PublicRoute cũng chuyển hướng sang /dashboard (

return <Navigate to="/dashboard" replace />;
).
Bước 2: Router nhận yêu cầu đi tới đường dẫn /dashboard. Tuy nhiên, trong danh sách các <Route> bên dưới, không hề có route nào khớp với path /dashboard.
Bước 3: Vì không có route nào khớp, Router sẽ rơi vào route catch-all ở cuối file: 

<Route path="*" element={<Navigate to="/" replace />} />
 và chuyển hướng người dùng quay trở lại /.
Bước 4: Tại /, ứng dụng lại thực hiện bước 1 (chuyển hướng sang /dashboard), tiếp tục lặp lại các bước trên tạo thành vòng lặp vô hạn. React phát hiện số lần re-render vượt quá giới hạn cho phép và throw lỗi crash app.

3. Lưu ý thêm: Lỗi lệch kiểu dữ liệu (Type Mismatch) trong Sidebar
Sau khi sửa xong lỗi điều hướng trên, bạn có thể sẽ gặp một lỗi logic nhỏ khác khiến các menu con (SubModules) khi click vào đều bị nhảy sang trang /coming-soon:

Trong 

types/index.ts
, moduleMasterSubID của interface SubModuleInfo là kiểu string:
typescript
export interface SubModuleInfo {
    moduleMasterSubID: string; // <-- kiểu string (ví dụ: "2")
    ...
}
Trong khi đó, hàm getSubModuleRoute tại 

routesConfig.ts
 lại yêu cầu tham số thứ hai là number:
typescript
export const getSubModuleRoute = (
    moduleMasterID: string,
    subModuleMasterID: number // <-- kiểu number
) => { ... }
Vì sử dụng toán tử so sánh nghiêm ngặt ===, việc đối chiếu giữa 2 (number) và '2' (string) sẽ trả về false, khiến hàm không tìm được route chính xác.

Giải pháp sửa nhanh: Ép kiểu number trước khi truyền vào hàm tại file 

Sidebar.tsx

+ const route = getSubModuleRoute(sub.moduleMasterID, Number(sub.moduleMasterSubID));
